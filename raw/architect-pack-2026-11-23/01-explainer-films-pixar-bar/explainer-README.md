# Meridian Explainer Series — template runbook

Storytelling explainers with Holmes & Watson: posed Blender stills of the
game's pair, production TTS voices, and Remotion camera moves over the
stills. Episode 1 (the Moon) was built one-off; everything since runs on
the reusable template in `template/`. The original one-off code
(`src/moon-index.jsx`, `moon/build_scene.py`) stays as the reference.

## The format (proven, do not re-derive)

- **Posed stills, not animation.** EEVEE on this VM runs only under
  xvfb/software-GL at ~110 s/frame — a full animation would take ~32 h.
  Stills + camera moves carry the story.
- 1280×720, 30 fps, h264 + AAC, loudnorm **−16 LUFS**.
- Voices: Holmes `avocado_v2:atlas`, Watson `avocado_v2:pb1_music_02`,
  speed 100, via `/opt/hatch/bin/tts`.

## Episode folder

```
episodes/<slug>/
  episode.json   title, question, style (roulette), beats, cards, theme
  stills.json    shot list for the Blender still engine
  stills/        posed stills (s1_*.png, ...)
  audio/         per-line TTS clips (L1.mp3, ...)
  timing.json    generated by the TTS step — per-line start/duration
```

`episode.json` beats: `{speaker, line, caption?, shots[]}`. A shot:
`{still, cameraMove, zoomFrom, zoomTo, panX, panY, snapTo, at?}` — `at`
is an absolute start second; without it a shot starts at its beat's line
start (0 for the first beat). A shot ends where the next one starts.

## Make an episode

1. **Write it.** Create `episodes/<slug>/episode.json` (copy
   moon-phases and edit). Pick the episode's `style` — the series draws
   a per-episode visual style from the owner's boards (Paper Cut, Anime,
   Watercolor, Pixel Art, Comic, Low-poly 3D, …); episode 1 is
   `game-3d`. Script lines are sourced facts, never invented.
2. **Voice it.** `npm run tts -- <slug>` — synthesizes each beat with the
   speaker's voice into `audio/L<n>.mp3` and writes `timing.json`
   (lead-in 0.5 s, 0.3 s gaps; `--force` re-voices). ~20 s total.
3. **Pose the stills.** Write `stills.json` (named poses from the game's
   pose table — ARMS_DOWN, HOLD, HOLD_HIGH, THINK — with per-field
   overrides, or full pose values; placement `home`/`orbit`, camera
   `wide`/`orbitClose`), then:
   `xvfb-run -a ~/workspace/tools/blender-4.5.16-linux-x64/blender -b --python template/blender/still_engine.py -- episodes/<slug>/stills.json`
   ~2.2 min per still (63 s measured for a wide shot). Sets live in
   `template/blender/sets/`; `moon_room` is the lamp-room set.
4. **Render.** `npm run render-episode -- <slug>` — renders the
   data-driven `Episode` composition with the episode folder as the
   public dir, then loudnorms to `out/<slug>.mp4`. ~4–5 min.
5. **Check it.** Duration ≈ timing total, 1280×720, loudness ≈ −16 LUFS
   (`ffmpeg -i out/<slug>.mp4 -af loudnorm=print_format=json -f null -`),
   spot-check the first, middle, and end frames.

Steady state once the set exists: **~30 min of machine time per episode**
(stills dominate). New sets are the expensive part, not new episodes.

## Camera moves (template/src/cameraMoves.js)

DollyIn · DollyOut · Settle · Drift · LowArcAround · BackwardOrbit ·
Close-up · SnapZoom · Crane · SnapCrane · Tilt · PendulumSwing ·
Ground-Skim · FPV. Each is a preset over per-shot params
(`zoomFrom/zoomTo/panX/panY/snapTo`) — name the move in episode.json and
tune the numbers, never write per-episode animation code.
