## 0. The reading (Reality Checker's line, adopted verbatim)

> READING: "all editions" = Globe/Country/State pin-drop only. GeoDetective + Cold Trail OUT of this design. Overrule: say "include them".

**GeoDetective — OUT.** Mechanical reasons: its guesses are NAMED place picks in a different id namespace (`geonames:` ids, not `gn-*`); its content unit is ONE mystery place vs the codec's 5–10 id route; it has no Run/radius/scoring-version machine (identity = clue-file index in its own deck store); and a shareable payload naming the mystery would BE the answer — the mode is spoiler-fragile in a way pin routes are not. Its future form is a separate "mystery dare" feature (same mystery, race on clues/guesses used) with its own council.

**Cold Trail — OUT.** Mechanical reasons: its content unit is a build-time case (`caseNo`: 3 sightings + 1 hideout), not a dealt id list; scoring is raw km-from-hideout under its own wallet/stars economy; the codec cannot carry its case identity and its isolation rules are a separate economy's. The Game Designer's `caseNo`-payload sketch is recorded in `BRAINSTORM.md` as the strongest future candidate — a separate feature, not a rider on mc2.

## 1. Decision table — edition × phase

Radii are per-EDITION and identical across all phases: **Globe 750 km** (flat) · **State `radiusKm` = 12% of the region's greater side, clamp [25, 160]** (Rhode Island 25 floor · Nebraska ≈87 · Texas ≈160 cap) · **Country `radiusKm` = 12% of greater side, clamp [40, 450]** (UK ≈147 · USA 450 cap). The radius is computed at creation from the named region, pinned into the link as a whole-km integer (`rad`), snapshotted onto the run at receive, and read by BOTH judgement sites through one accessor. It is the FINAL judgement radius — no age-band multiplier applies on top in a challenge run (the shipped Globe freeze semantics, generalized). A pin at exactly the radius is a HIT (`isHit = distance <= radius`, verified in `src/game/radius.ts`).

| Phase | Entry point | What it deals | Player-facing label |
|---|---|---|---|
| (a) Picker / home | Button under Play, rendered only when the selection is complete + flag on + eligible pool ≥5 | **Fresh deal, 5 places**, from the picker-selected (edition, region) catalog, filtered by the picker's difficulty band; region = deepest playable node selected (drilled to Nebraska ⇒ State/Nebraska) | "Challenge a friend" → preview sheet: "{N} places · {Region} · {radius} km circle" + "a new route in {Region}" |
| (b) Mid-run (aim) | **Run-menu item only** — no new aim-surface chrome, separated from End game | **Fresh deal, 5**, from a snapshot of the run's region pool; widening chain (all steps stay INSIDE the named region): run pool → region pool band-filtered, seen-included → full region catalog | "Challenge a friend — new route in {Region}" → preview sheet |
| (c) Reveal (story/done) | Text link in the result-card footer, below Next place | **Fresh deal, 5**, same source as (b) | "Challenge a friend in {Region}" + non-interactive hint line "Your route unlocks when you finish 🏁" |
| (d) End-of-game summary | Primary + secondary actions at the shipped summary location | **Primary: the sender's actually-played places**, in play order, first 10 if more were played, offered only when ≥5 were played. **Secondary: fresh deal, 5**, same region | Primary "Challenge a friend — play my route" (preview sheet carries the disclosure: "This shares the exact places you just played, in order.") · Secondary "New route in {Region} instead" |
| (e) Review deck / review-complete | Deck-level entry only — never per-card | **Fresh deal, 5**, from a region chosen in a mini-picker (edition + region). **NEVER the deck's own cards** (see §3 privacy note) | "Challenge a friend — pick a map" → preview sheet |
| (f) Challenge-complete | Primary share on the completion takeover (immediate share, as shipped — the one surface with no preview sheet) | **The exact route just played**, re-encoded in its ORIGIN format (mc1 in → mc1 out; mc2 → mc2; never downgrade). Secondary: fresh deal, 5, from the completed route's region | "Pass this challenge to a friend" + pre-written reply text "I scored {X} on your {Region} route — beat that!" · Secondary "Or send a new {Region} route" |

**Fresh-deal rules (all phases):** fixed length 5 (exact shares keep their real N, 5–10); dealt ids are ORDERED tier-ascending (famous first — the ladder as presentation; sampling weights unchanged, fame-weighted dealing stays the owner's separate open item); creation is a pure read + fresh deal — it never mutates the live run, dealer, seed, or pool, and never reads the dealer's upcoming queue; creation is click-atomic w.r.t. the flag (gate checked at tap, never render-time only). If no source in the widening chain can supply 5 places, NO control is offered — never a short, padded, or repeat-filled route.

**Share text:** one verb ("Challenge a friend"), region phrase per edition replacing the hardcoded "on the Globe!" (`run-summary.tsx:86–87`); every result share carries the denominator — score + place count + region (Economy Designer's rule); mc2 share texts add the line "(Opens in the newest Meridian.)" (§6, C12 mitigation). No sender name anywhere — links are accountless; a name field would be unverifiable free text shown to children.

## 2. Codec verdict — mc2, mc1 frozen

**Verdict: v1 is NOT sufficient. A sibling format mc2 is required; mc1 is frozen byte-identical.**

- Extending mc1 in place is impossible, not merely inadvisable: its decoder rejects any key set other than exactly `{v,e,s,ids,seed}`, any `v≠1`, any `e≠"globe"` (verified in `src/game/challenge.ts`). A region field breaks the key set; reusing `e` cannot express Country/State.
- **mc2 wire format:** prefix `#c=mc2.` + base64url JSON, fragment ≤2000 chars, canonical encoding, fail-closed — mc1's discipline inherited. Payload keys EXACTLY `{v, e, r, rad, s, ids, seed}`:
  - `v` = 2 · `e` ∈ `{"globe","country","state"}` · `r` = region slug (`"globe"` iff `e="globe"`; otherwise a slug playable for that edition — the pair (e, r) is the identity, always read together, including in display/logging: "Georgia" the state vs "Georgia" the country is disambiguated by `e`, never by the slug alone)
  - `rad` = the frozen radius as a **whole-km integer** pinned at creation
  - `s` = `SCORING_VERSION` (currently 3) · `ids` = 5–10 unique `/^gn-[0-9]+$/` · `seed` = FNV-1a integrity hash over a canonical string covering `v+e+r+rad+s+ids`
- **Dispatch:** boot keeps the `startsWith("#c=")` catch-all (every challenge-namespace fragment is stripped synchronously and can never endanger the saved run); inside it, exact-prefix dispatch — `mc1.` → the frozen mc1 decoder, `mc2.` → the mc2 decoder. Two strict per-version decoders (a unified decoder was rejected: cross-version field bleed); results normalize to one internal model `{edition, regionId, radiusKm, ids, originFormat}`.
- **Radius trust rule (amended under Councilor C's challenge — see §7, items 2–3):** the pinned `rad` is honoured only if it matches the receiver's OWN computed radius for the named (e, r) **within ±10%** (Globe: exactly 750, tolerance zero), AND sits inside the edition sanity envelope (state [25,160], country [40,450]). Outside either bound → fail closed, reason `"radius"`. This binds the radius to the named region (a Rhode Island link at rad=160 is rejected even though 160 is inside the state envelope), survives minor bounds corrections (<10% drift keeps old links valid, judged at the sender's pinned radius — the comparability property pinning exists for), and fails forgeries that merely satisfy the envelope. Threat model recorded honestly: FNV-1a is an integrity checksum, not authentication; links are bearer game invites with no backend, no reward, nothing leaving the device. The binding is a fairness control, not a security boundary — the same trust level as mc1.
- **Back-compat contract for live mc1 links (IN THE WILD — breaking them is a named failure mode):**
  1. The mc1 decoder, its strictness, boot behaviour, saved-run resume, and re-share are untouched. Contract suite: the pre-existing mc1 blocks of `src/game/challenge.test.ts` pass **byte-unmodified** (PR-diff enforced).
  2. Golden vectors are **REAL links captured from the shipped `b09a5c3` build** — ≥3 links, pairwise-distinct id sets, with provenance metadata (build hash, capture date, method) in `src/game/__fixtures__/mc1-captured-links.json`. Synthetic vectors are self-fulfilling and are rejected as evidence. mc2 decode is additionally pinned against hand-written payload fixtures with an in-test FNV-1a re-implementation, so encoder and decoder cannot share a bug silently.
  3. Re-share preserves origin format whenever it can fully express the run: mc1 in → mc1 out; mc2 → mc2; an mc2 Country/State run is NEVER downgraded to mc1 (the region would be lost and the route misjudged as Globe).
  4. New Globe creations are emitted as mc2 (rad=750 pinned). mc1 remains decode + mc1-origin re-share only.
  5. **Scoring-version cliff — named, with a mechanism, not just prose (amended under C item 5):** today's gate (`s` must equal the CURRENT `SCORING_VERSION`) means the next scoring bump kills every live mc1 link — and mc2 links share the same cliff. This build ships a **tripwire test**: a unit test pinning `SCORING_VERSION === 3` whose failure message states that bumping the constant kills live family-chat links unless frozen-version judging ships in the same PR. Whether to pay for frozen-version judging NOW (a version→judging-params registry; mc1 judged as v3 forever) is Open Question 3 for the owner; Councilor C's objection to deferring it is carried verbatim in §8.

## 3. Run model, isolation, persistence

- **Identity:** challenge runs keep `regionId === "challenge"` — the sentinel every isolation guard keys on (`game-app.tsx:355–368` and guards at `:4281–4295`, `:4330`, `:4445–4458`). A NEW Run field carries the challenged region slug, meaningful only on challenge runs; new writes always write the slug (`"globe"` included); the resume validator treats an ABSENT field as `"globe"` (legacy mc1 saves only). The run snapshots `challengeRadiusKm` at start; both judgement sites (`game-app.tsx:4653` reveal, `:4689` onConfirm) read it through ONE accessor. `boundsFor` consults the field for challenge runs (today it returns `[0,0,0,0]` for `regionId "challenge"` — map framing resolves to the challenged region's bounds).
- **Definitions (amended under C item 1):** "region pool" in the receive chain means the region's CATALOG assignment — every id `placesFor(edition, regionId)` can return for that (e, r) BEFORE band/seen filtering. Creation's widening chain never leaves the named region, so every creatable link passes receive membership by construction; a contract test asserts creation→receive acceptance for every widened deal shape (B 5.8 fixtures fed through the receive validator).
- **Receive validation chain** (fail-closed at each step; every failure → child notice + fall-through, no partial run): flag + prefix → strict per-version decode → version/scoring gates → (e, r) pair legality → region exists and is playable for that edition → radius binding (§2) → seed integrity → catalog load for exactly (e, r) → EVERY id a member of that region's catalog assignment (global existence is insufficient — the same gn id legitimately lives in a state chunk and its country aggregate) → completeness (count, no duplicates, full resolution).
- **Failure copy — three remedy classes** (player never sees internal reasons `format|version|scoring|edition|region|radius|tooBig|load`):
  1. *Link broken* (format/version/scoring/edition/seed/radius/tooBig): "Could not load this challenge." + "Ask your friend to send the link again."
  2. *Content unknown to this build* (unknown region slug / unknown id / catalog miss): "Could not load this challenge." + "This route visits a place this version of Meridian doesn't know yet."
  3. *Couldn't load* (region chunk/network failure on receive — added under C item 12): "Could not load this challenge." + "Check your connection and tap the link again."
  Flag-off receipt stays SILENT — indistinguishable from no link.
- **Isolation (extended per edition, unchanged in kind):** challenge runs never bank session score, never write learning records, never add review-deck cards, never write persistent seen history — for Globe, Country, and State alike, all keyed on the sentinel. The receiver's own seen history never shrinks a received route. Per-edition E2E isolation suites with sentinel controls and mutation proofs are mandatory (B Group 6).
- **Privacy note (recorded under C items 9 + 11):** the summary exact-route share is a DELIBERATE privacy trade vs v1's fresh deal — the link documents what the sender played, in order, to whoever holds it. It ships because the honesty ruling (§1d) requires the primary share to be the played route; the preview sheet's disclosure line is the mitigation. "Never the deck" is claimed precisely: it prevents CASUAL ONE-TAP disclosure of the sender's misses (deck ids are decodable from any link that carries them); it does not and cannot make misses unpublishable by a determined sender.
- **Receiving & displacement (amended under C items 6–7):** a valid link boots to the **welcome card** — "A challenge from a friend!" / "Find {N} places in {Region}. Get inside the {radius} km circle — closer is better!" / "Same places, same circle for everyone." / progress-safety line / Start. **Displacement commits only on the Start tap:** opening a link never destroys anything; until Start, a saved challenge run remains intact and resumable, and a saved NORMAL run is never displaced at any point (it survives underneath a started challenge and is offered back intact afterwards). Resuming a saved challenge run does NOT re-show the welcome card (receive-time only). **Fall-through guard table:** flag OFF → no challenge run ever boots or resumes (saved challenge runs are cleared per the shipped rule; the normal run is never collateral); flag ON + failed link + saved challenge run → the saved challenge resumes, and the distinguishing signal is the failure notice shown first plus the resumed run's own region pill ("🤝 {Region} challenge", progress "k / N").
- **Downgrade safety (amended under C item 8):** mc2-origin challenge saves persist under a **NEW storage key that `b09a5c3` builds never read** — isolation by construction, so an old build boots as if no challenge run exists and its blast radius can never reach the normal-run slot. mc1 challenge saves stay in the existing slot. B's substitute evidence is retained on top: unknown-field tolerance units + the scripted `@old-build` manual rehearsal (serve `b09a5c3`, inject the new-shape save, assert clean fall-through boot), executed once by QA and recorded in the verification ledger before the PR is merge-ready.

## 4. Flag behaviour

- `friendChallenges` (default `false` in `src/lib/flags.ts`; prod `flags.json` true) remains the single gate, fail-closed. ONE shared creation component carries the gate — never per-surface flags.
- Flag off = the feature does not exist: no creation control on any of the six surfaces (E2E sweep is a merge gate), links boot indistinguishably from no link, saved challenge runs do not resume.
- Flag on at render but off at tap → no fragment is produced and no clipboard/share write occurs (click-atomic gate, B 5.13).
- A challenge run already in flight when the flag flips continues to completion; its ChallengeComplete keeps Done but drops re-share (creation is not continuation).
