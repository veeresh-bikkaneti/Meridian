## Decisions

- **D1 — Storage key: the shipped constant wins over the brief's
  spelling.** The task brief says "New key: `meridian:palette`"
  (colon). The already-merged-to-branch code says
  `PALETTE_STORAGE_KEY = "meridian.palette"` (dot), and
  `palette.test.ts` asserts that exact value. The dot form is also
  the settings family form (`meridian.sound` for the mute toggle).
  Changing the key would break the shipped fail-closed contract for
  zero player benefit and would orphan any value a preview build
  already stored. **Decision: all reads/writes go through
  `PALETTE_STORAGE_KEY` from `palette.ts`; stored values are
  `"high-contrast"` and `"standard"` — exactly `selectPalette`'s
  token language.** This deviation from the brief's literal spelling
  is recorded here, in the run report, and in the PR body.
- **D2 — `palette.ts` stays pure; a new module owns storage + DOM.**
  `palette.test.ts` pins `palette.ts` free of
  `document|localStorage|fetch|window`. So
  `src/game/palette-preference.ts` mirrors the `src/game/audio/sfx.ts`
  pattern exactly: a `storage()` helper behind try/catch (absent or
  throwing storage reads as standard, writes are silent no-ops),
  `readPalettePreference(): MapPalette` =
  `selectPalette(storage()?.getItem(PALETTE_STORAGE_KEY))`,
  `isHighContrastEnabled()`, `setHighContrastEnabled(on)` writing
  `"high-contrast"` / `"standard"`, and
  `applyPalettePreference()` which sets
  `document.documentElement`'s `data-palette="high-contrast"`
  attribute (removing it for standard) and dispatches
  `window` `CustomEvent("meridian:palette-change")` — the
  `meridian:sound-change` precedent (`sfx.ts`, listeners in
  `grandpa-ask.ts` / `storyteller.tsx`). Never throws.
- **D3 — Application mechanism: CSS vars, the existing token pipe.**
  Map colours already flow as `--map-*` custom properties in
  `src/styles.css`, read per paint by `src/map/colors.ts`
  `readColors()` (`paint-scene.ts`, `atlas-map.tsx`, the globe).
  `src/styles.css` gains one block, placed after the
  `:root[data-theme="night"]` block so it wins at equal specificity
  over every theme:
  `:root[data-palette="high-contrast"] { --map-water: #0b0d10;
  --map-land: #f6f3ea; --map-arc: #c45c12; --map-lake: #1a1d22;
  --map-coast: #050608; }` — the five `HIGH_CONTRAST` values, no
  other var touched. A source-pin test (B) asserts this block's
  values equal `HIGH_CONTRAST` so CSS and tokens cannot drift.
- **D4 — Live swap without reload, per surface.**
  (a) Vector/canvas paints: `readColors()` is called on every draw,
  so a var change lands on the next paint; `atlas-map.tsx` gains a
  targeted listener block for `meridian:palette-change` that flags
  the basemap dirty and requests a redraw in place — no remount, no
  navigation, the run/round state is untouched.
  (b) Satellite (MapLibre) map: the dashed ring layer's
  `"line-color": "#f4f1ea"` is exactly `STANDARD.arc`. At style load
  it takes the active palette's `arc`; a targeted listener effect
  calls `map.setPaintProperty(RING_SOURCE, "line-color", arc)` in
  try/catch when the layer exists. Nothing else in the satellite
  style changes — satellite imagery is photography and is not
  recoloured; the palette governs the map tokens drawn over/under
  it (fills, arc/ring), which is what `palette.ts` defines.
  (c) The toggle itself: React state in the toggle component (the
  `SoundToggle` pattern — each host reads the persisted value on
  mount), plus the D2 event so mounted maps repaint in the same
  interaction.
- **D5 — GeoDetective readability is a non-touch guarantee.**
  GeoDetective is the one labelled edition: guesses are made on a
  labelled satellite tap surface, and the labels ARE the game
  (`AGENTS.md` Project invariants). The palette wiring must not hide,
  dim, recolour, or restyle any label, place-name marker, or label
  layer, and must not change label visibility at any zoom. The only
  satellite-map changes are D4(b)'s ring colour. The distance label
  element (`#f4f1ea` on `#101211`) is untouched and unchanged in both
  palettes. B pins this with a source test: the implementation diff
  for `satellite-map.tsx` touches no label code (reviewed at gate
  time against this manifest), and the E2E corrupt-value case proves
  the app still boots and plays, labels included, on fallback.
- **D6 — Toggle UI mirrors the mute toggle.** A
  `HighContrastToggle` component in `game-app.tsx` beside
  `SoundToggle`, same shape: `useState` initialised from the
  persisted preference, `aria-pressed`, `aria-label` "Turn high
  contrast on" / "Turn high contrast off", `title`, and the same two
  hosts — home hero (`data-testid="high-contrast-toggle"`,
  `atlas-sound-toggle` class, ≥44×44 px) and in-game chrome
  (`data-testid="high-contrast-toggle-game"`). Flipping it writes
  storage, applies the attribute, dispatches the event, and updates
  state — in that order, inside try/catch so the toggle never
  throws. Unlike the Scout Map toggle it never ends a game and never
  navigates: high-contrast is a paint choice, not a map-build input.
- **D7 — Boot applies the stored preference.** GameApp gains one
  mount effect calling `applyPalettePreference()`, so a stored
  `"high-contrast"` reaches the CSS vars and any map that paints
  after boot, on every GameApp-hosted screen — home, the three quiz
  editions, and GeoDetective (LoopScreen is hosted inside GameApp).
  No reload-time flash claim is made: the effect runs post-commit,
  like the flags kill-switch precedent in `__root.tsx`.
- **D8 — Fail closed everywhere.** Unknown, corrupt, empty, or
  wrong-case stored values, a throwing `localStorage`, and a missing
  palette all resolve to `STANDARD` via `selectPalette` — never a
  crash, never a broken map, never a third state. This is the
  shipped `palette.ts` behaviour; this feature only consumes it.

## 1. ATDD acceptance scenarios (Councilor A — child-observable)

- **Scenario 1 (happy path, toggle on):** Given I am on the home
  screen and the map colours are the usual ones, When I tap the
  high-contrast button (I can see it pressed and hear its name say
  high contrast is on), Then the map colours change right away to
  the strong black-and-cream map with the orange line — without the
  page reloading and without my game or place being lost.
- **Scenario 2 (persistence):** Given I turned high contrast on,
  When I reload the page, Then high contrast is still on and the
  button still shows it is on.
- **Scenario 3 (toggle off):** Given high contrast is on, When I tap
  the button again, Then the usual map colours come back right away,
  the stored value says standard, and nothing reloads.
- **Scenario 4 (corrupt stored value — failure path):** Given
  something put a nonsense word in the palette storage slot, When
  the app boots, Then it opens with the usual map colours, nothing
  is broken, and I can still start and play a game.
- **Scenario 5 (storage unavailable — failure path):** Given the
  browser refuses storage (private mode), When I tap the toggle,
  Then nothing crashes; the colours change for now or stay usual,
  and the game plays on.
- **Scenario 6 (mid-run live swap — boundary):** Given I am in the
  middle of a game round, When I tap the in-game high-contrast
  button, Then the map colours change in place, my pin, the round,
  and the score are exactly where they were, and I am not sent home
  (unlike the Scout Map switch).
- **Scenario 7 (GeoDetective labels — boundary):** Given I am
  playing GeoDetective with high contrast on, When I look at the
  guess map, Then every place label I could read before is still
  there and still readable — high contrast never hides the names,
  because the names are how I guess.
- **Scenario 8 (contrast floor — boundary):** Given either palette,
  When the reveal line is drawn over water or over land, Then a
  test can measure the line against both backgrounds at ≥3:1 — in
  BOTH palettes, not only high-contrast.

## 5. Adversarial challenge (Councilor C — Accessibility Auditor)

C's challenges, each with its disposition recorded before sign-off:

1. **Corrupt localStorage value.** A hand-edited or legacy value
   (`"HIGH-CONTRAST"`, `"true"`, `1`) must never select
   high-contrast or throw. → **Adopted as D8 + B's corrupt-value
   unit and E2E contracts.** `selectPalette` already fails closed;
   the new module adds no second parser.
2. **Palette token missing.** If a future palette lacks a token,
   `readColors()` falls back per-var and `selectPalette` returns a
   whole palette object — there is no partial-palette state. →
   **Adopted:** D3 overrides all five defined tokens together; the
   CSS source-pin test fails if any of the five is dropped from the
   block.
3. **GeoDetective labelled map readability.** Any solution that
   recolours or hides labels fails the edition's core mechanic. →
   **Adopted as D5 (non-touch guarantee).** Residual risk recorded:
   no automated E2E in this round plays a full GeoDetective mystery
   in high-contrast; the guarantee rests on the diff discipline +
   the satellite source review at gate time. The Chair accepts this
   because the wiring provably cannot reach label code (footprint),
   and flags it as the report's least-sure item if it remains so.
4. **Live swap mid-run.** A swap that remounts the map, ends the
   run, or strands focus fails Scenario 6 and the Scout precedent's
   hard-won lesson (a settings flip must say what it does — this
   one does nothing but repaint, so it needs no warning copy and
   must do no navigation). → **Adopted as D4 + D6**; E2E live-swap
   case asserts same URL + aim phase survives.
5. **Contrast floor edge cases.** The brief's Stage-3 claim says the
   arc is ≥3:1 on water AND land — the existing test proves it only
   for HIGH_CONTRAST. STANDARD arc `#f4f1ea` on land `#3c4a3c` must
   be measured, not assumed; and the toggle's own label/icon must
   meet the text/UI floors on both home themes. → **Adopted:** B's
   STANDARD arc contract (§2) with a STOP if RED; the toggle
   reuses the `atlas-sound-toggle` brass treatment whose focus
   style already ships, and no new text-on-map surface is created.
6. **Flakiness / vacuous assertions.** E2E must not sample canvas
   pixels (software rendering varies) and must not assert only a
   data-attribute label while the feature does nothing (the Scout
   label-only bug, 2026-10-20). → **Adopted:** E2E asserts the
   computed CSS var values (feature-level truth for every
   `readColors` consumer) plus persistence plus in-run survival.

C's closing line, verbatim as required by the protocol:

Dispositions: challenges 1–6 adopted as binding constraints
