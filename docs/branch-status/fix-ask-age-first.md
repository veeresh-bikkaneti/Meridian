# fix/ask-age-first — branch status

**Task:** Implement the owner's decision of 2026-11-14 ("Ask first"): a player with no age band set must be asked to pick one before any case starts — never silently default to 10-18. This settles the open owner call PR #485 flagged (first-run prompt vs the silent default). Draft PR only — the owner (Veeresh) merges. Built on current main `5fe47c1c`.

**Scope — the fallback census.** The silent default lives in one place (`resolveBand()` / `getAgeGroup()` in `src/game/age-profile/store.ts`: an unset profile resolves to `FULL_ACCESS_BAND`, "10-18"). Every production read of it was traced and classified; the gate sits at the case-start paths, and the store's read contract itself is unchanged (display and lock reads below keep it, deliberately):

- **Gated (case starts):**
  - The Why Learn card (`game-app.tsx`): the tap now runs through `askAgeFirst`, which holds the picker open behind the ask; the pick continues into the picker, which mounts at the picked band.
  - Subject cards (`SubjectPicker.openSubject`): the case load runs through GameApp's gate, passed down as the `onAskAgeFirst` prop; the continuation is the tapped subject's own load, so the intended case survives the ask. This also covers the one way the picker can be on screen with no band set: a grown-up resetting the profile from the hosted settings re-deals the list under the store's full-access read — a subject tap from there now asks first too.
  - "Resume your case": the subjects branch's resume control and Home's GeoDetective card in its resume mode (a mystery mid-play, `peekLoopProgress().inProgress`) both ask first; the resume itself still runs the shared `openGeoDetective` tap-in verbatim, and the subjects still close behind a successful resume.
- **The gate (`src/components/age-profile/AgeAskGate.tsx`, new):** hosts prod's own `AgePicker` verbatim (same cards, copy, save contract — no new look) for an unset profile and writes the pick through the store's unset path (`setBand`, the exact call the settings flow makes for a first set) before running the held continuation. It lives in the age-profile UI module so store mutations stay inside that module, as the facade's rule requires. There is deliberately no grown-up gate on it: that gate guards *changing* a set band in `AgeProfileSettings`, which is untouched. Backing out ("Not now") clears the hold — no write, no case. The hold is session-only state in GameApp and is dropped by the `pageshow` back/forward-cache handler with the tap-in screens it guards.
- **Left, with reasons (noted for the owner):**
  - A *fresh* GeoDetective deal from Home's card (no mystery in progress): a main-game loop start. Runs and loop deals snapshot `getBandConfig(loadProfile().band)` — the profile's RAW band — with a deliberate no-profile default (run-config `DEFAULT_HINT_POLICY`, owner 2026-10-20); the decision named Resume, not fresh deals. Widening the gate to fresh deals is a one-line change to the card handler if the owner wants it (plus band seeds for the detective e2e suite).
  - The friend-challenge deep link (`#c=…`): for mc2/mc3 links no gameplay starts on arrival — a welcome card shows and displacement commits on an explicit Start tap (a main-game run start, same raw-band family); its boot is manifest-governed (a link tap must never lose a saved run), so it is not gated. For mc1 links the boot does start a run on arrival, with no welcome card — that path is frozen and manifest-governed, and its run is a main-game run on the same raw-band snapshot family as the fresh deals, so it sits in the same exempt family (reviewer correction, 2026-11-15: the welcome-card reason does not cover mc1).
  - Boot resume of a saved run (`bootSavedRun`): the run's band config was snapshotted at deal time; nothing re-reads the fallback.
  - Display/config reads inside play: `SubjectCase`'s `group ?? getAgeGroup()` (production mounts always pass the picker's band), `SubjectPicker`'s initial band and change-event re-read (the list is not a case start; the case open behind it is gated), `result-card.tsx` story/audio reads, `generated-places.ts` story mapping, `game-app.tsx`'s boundary story read and the `ageBand` lock reads (`isLoopLocked` etc. — locks must fail open for an unset profile, never strand a child), Cold Trail's band state (a main-game loop screen, same family as the fresh deals).
- Bands are exactly the band table's: 7-10, 10-18, 18+ — nothing under 7, nothing re-authored. No `docs/scaling/**` data file is touched.
