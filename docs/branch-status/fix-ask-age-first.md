**Scope — the fallback census.** The silent default lives in one place (`resolveBand()` / `getAgeGroup()` in `src/game/age-profile/store.ts`: an unset profile resolves to `FULL_ACCESS_BAND`, "10-18"). Every production read of it was traced and classified; the gate sits at the case-start paths, and the store's read contract itself is unchanged (display and lock reads below keep it, deliberately):

- **Gated (case starts):**
  - The Why Learn card (`game-app.tsx`): the tap now runs through `askAgeFirst`, which holds the picker open behind the ask; the pick continues into the picker, which mounts at the picked band.
  - Subject cards (`SubjectPicker.openSubject`): the case load runs through GameApp's gate, passed down as the `onAskAgeFirst` prop; the continuation is the tapped subject's own load, so the intended case survives the ask. This also covers the one way the picker can be on screen with no band set: a grown-up resetting the profile from the hosted settings re-deals the list under the store's full-access read — a subject tap from there now asks first too.
  - "Resume your case": the subjects branch's resume control and Home's GeoDetective card in its resume mode (a mystery mid-play, `peekLoopProgress().inProgress`) both ask first; the resume itself still runs the shared `openGeoDetective` tap-in verbatim, and the subjects still close behind a successful resume.
- **The gate (`src/components/age-profile/AgeAskGate.tsx`, new):** hosts prod's own `AgePicker` verbatim (same cards, copy, save contract — no new look) for an unset profile and writes the pick through the store's unset path (`setBand`, the exact call the settings flow makes for a first set) before running the held continuation. It lives in the age-profile UI module so store mutations stay inside that module, as the facade's rule requires. There is deliberately no grown-up gate on it: that gate guards *changing* a set band in `AgeProfileSettings`, which is untouched. Backing out ("Not now") clears the hold — no write, no case. The hold is session-only state in GameApp and is dropped by the `pageshow` back/forward-cache handler with the tap-in screens it guards.
- **Left, with reasons (noted for the owner):**
  - A *fresh* GeoDetective deal from Home's card (no mystery in progress): a main-game loop start.   - Display/config reads inside play: `SubjectCase`'s `group ?? getAgeGroup()` (production mounts always pass the picker's band), `SubjectPicker`'s initial band and change-event re-read (the list is not a case start; the case open behind it is gated), `result-card.tsx` story/audio reads, `generated-places.ts` story mapping, `game-app.tsx`'s boundary story read and the `ageBand` lock reads (`isLoopLocked` etc. — locks must fail open for an unset profile, never strand a child), Cold Trail's band state (a main-game loop screen, same family as the fresh deals).

## Amendment — band selection contained on the picker page (2026-11-15)

Radhae's reconciliation of the #497/#498 overlap (voice call 2026-11-15): everything band-related stays inside the Why Learn workflow — there is no player-facing settings screen, so graduation must be possible from the picker page itself. This section supersedes the two census bullets above that describe the Why Learn card and the subject cards routing through the modal gate; everything else in the census stands.

**What changed:**
- New `src/components/age-profile/AgeBandControl.tsx`, hosted by `SubjectPicker` directly under the hero card. It lives in the age-profile UI module, so it may use the store's write functions directly, per the facade rule.
  - No band set: the control shows the three band pills (the shared `Button`, pill-shaped; labels and order from the band table — "Ages 7-10 / 10-18 / 18+") under the picker's own first-set line ("Pick the closest — you can change it anytime."). A pick writes via `setBand` (the store's unset path); the picker's existing `ageprofile:changed` subscription re-deals the list.
  - Band set: the pills collapse to a "Change band" button. Tapping it re-opens the pills with the current band marked; picking a different band writes via `saveBand` with the settings flow's `runInProgress` input (`run !== null || loopOpen`, passed down from GameApp as `bandChangeRunInProgress` — the same value `AgeProfileSettings` receives); picking the current band just collapses, no write. The picker re-deals in place. This is the graduation path.
  - No parallel band state: the control's only state is the profile snapshot (re-read on every store change event, which also collapses the pills) and whether the pills are open; the pick itself re-reads the profile fresh before choosing the write path, so a stale snapshot can never pick the wrong one.
- The picker page asks itself now: GameApp's Why Learn handler opens the picker directly (the card leads TO the page; it does not bypass it — keeping the modal there would have made the first-run pills unreachable), and `SubjectPicker.openSubject` no longer routes through the modal gate. **Chosen subject-tap behaviour while unset:** the tap starts no case and takes the player to the pills (scroll + focus the first pill) — one ask on the page, not two; enforcement moved, not removed, since no case can start band-less. The picker's sub line names a band only when one is set ("Pick a subject" while unset).
- Unchanged: the modal `AgeAskGate` on the paths that bypass the page (Resume your case on Home's card and on case screens; deep links), the gate component itself, the 🔒 For grown-ups entry and `AgeProfileSettings` (byte-identical), and every "Left, with reasons" ruling in the census.
- Owner decision flagged in the PR body: "Change band" is an ungated control on a kid-facing page — deliberate per Radhae's direction (no player-facing settings exists); ratification is the owner's at merge. PR #497 is untouched; the PR body recommends closing it as superseded if this design is accepted.
