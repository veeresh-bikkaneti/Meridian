**Scope:**
- **Boot landing (1)** — `src/components/game-app.tsx`: no app state persists or restores a subject case (`subjectsOpen` is session-only `useState`, "Never persisted — a reload lands on Home"; the picker's `opened` state is session-only; boot consumes only `#c=` friend links). The one resurrection vector is the browser back/forward cache restoring the frozen single-page app with its state. A `pageshow` handler now closes the subjects picker and the GeoDetective loop when the page is restored from that cache (`e.persisted`, clearing the loop's stored flag via `writeLoopOpen(false)`, the pairing its own leave path uses), the same session-only rule as B7 (2026-11-09: the loop never auto-opens). Cold Trail's deliberate persisted open state is untouched.
- **End game (2)** — `src/components/ui/screen-shell.tsx` gains an optional `controls` slot in the header bar (Home, controls, sound — the GeoDetective cluster order); `src/subjects/shared/SubjectCase.tsx` renders the game's own End game button there (same `Button` secondary variant, same `data-testid="end-game-button"`, same 44 px floor as `LoopScreen`'s) wired to GameApp's `handleEndGame`, which ends the session and returns the player to Home. "Resume game" does not exist anywhere in the game (grep-verified across `src/`, `tests/`, `docs/`); the nearest equivalent is "Resume your case", the state of Home's GeoDetective card driven by the loop store (tapping reopens the in-progress mystery), plus boot auto-resume for interrupted runs. The original PR reported that as a finding and added nothing; **amendment (owner decision, 2026-11-14): the Why Learn screens get the control anyway, wired to that same real mechanism.** The picker and every case now render prod's own "Resume your case" button (same `Button` secondary variant, `data-testid="resume-case-button"`, 44 px floor) in the header controls slot, shown only when the loop store holds a mystery in progress (`peekLoopProgress().inProgress`) and the band is not loop-locked (`!isLoopLocked(ageBand, "geodetective")`) — the same condition under which Home's card offers it — and absent otherwise (never a disabled decoration). Tapping runs the card's own tap-in: the tap-in body was hoisted verbatim out of the Choose branch into a shared `openGeoDetective` callback in `game-app.tsx` (lock guard → storyteller-sendoff event → `writeLoopOpen(true)` → `setLoopOpen(true)`), which the card and the subjects branch both call — one implementation, no parallel resume logic. The subjects branch additionally closes the picker/case behind a successful tap-in, so leaving the reopened mystery lands on Home, exactly as leaving it from the card does. A subject case still holds no resumable state of its own, and an unsubmitted pick is simply left behind, as on any exit from a case — no confirmation dialog was invented.
- **Reset (3)** — the game's reset control (`ResetHistoryControl` + `RESET_HISTORY_COPY`, locked byte-exact per manifest 2026-10-28 §4) is extracted verbatim from `game-app.tsx` into `src/components/reset-history-control.tsx` — the lazy subject chunk must not import the app shell (the same reason the Living Atlas duplicated the hero overlays). GameApp renders the shared module on its existing surfaces unchanged. The picker and the case render it in a separated footer (Home's danger-footer placement rule), wired to GameApp's own `handleResetHistory`; a fully clean reset also leaves the subjects so the success toast shows on Home.
- **Age band (4)** — the picker keeps the band in state and subscribes to the age-profile change events, re-dealing its rows and closing any open case when the band changes (the settings flow's no-rug-pull rule). Its footer carries Home's exact grown-ups entry (`agep-footer` / `agep-footer-link`, `data-testid="grownups-link"`), and GameApp hosts the same `AgeProfileSettings` flow (gate → picker → confirm) over the subjects branch, with the picker inert behind it. No new picker UI: the gated settings flow is the game's only age-selection mechanism, and it is reused as-is. The six subject wrappers forward the two new optional case props (`onEndGame`, `onResetHistory`).
- No `docs/scaling/**` data file is touched; case behaviour (answer-blindness, phases, celebration, detective host, Home button) is unchanged; the hero film surface (`WhyLearnHero`) is untouched.
