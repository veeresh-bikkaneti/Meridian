# Security headers and caching (Cloudflare build)

**Single source of truth:** `src/lib/security-headers.ts` (`SECURITY_HEADERS`;
`HTML_CACHE_CONTROL` for the rendered-HTML caching header — see Caching).
They are delivered on two paths:

| Response | Who sets the headers |
| --- | --- |
| Worker-generated: every server-rendered HTML page (`/`, `/privacy`, …) and `/api/contact` | request middleware in `src/start.ts` (`withSecurityHeaders`); the same middleware also sets the rendered-HTML `Cache-Control` (`withHtmlCacheControl`, see Caching) |
| Static assets (`/assets/*`, `sw.js`, `flags.json`, `offline.html`, images, …) | `public/_headers`, which Vite copies into `dist/client/` |

Why two paths: Cloudflare documents that "custom headers defined in the
`_headers` file are not applied to responses generated by your Worker
code". The live `meridian` worker server-renders the HTML with TanStack
Start (`curl` on `/` shows per-request router state in the inline
dehydration script), so before this change the HTML never got the CSP,
XFO, HSTS, or COOP. An earlier version of this doc claimed it did. That
was wrong.

`src/lib/security-headers.test.ts` parses `public/_headers` and fails if
its `/*` block differs from `SECURITY_HEADERS`. `scripts/security-headers.test.mjs`
locks the policy content (no tracker hosts, frame-ancestors, caching).
GitHub Pages cannot set headers, so the Pages mirror gets none of them
(`_headers` is served there as an inert text file).

Defining `startInstance` in `src/start.ts` replaces TanStack's built-in
default request middleware (CSRF protection for server functions). It is
re-added there with the same filter, so that protection is unchanged.

## Headers on every path (`/*`)

| Header | Value | Why |
| --- | --- | --- |
| `Content-Security-Policy` | see below | limits scripts/connections to what the game needs |
| `X-Frame-Options` | `DENY` | no framing (legacy twin of `frame-ancestors 'none'`) |
| `X-Content-Type-Options` | `nosniff` | no MIME sniffing |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | outbound links (Wikipedia, Ko-fi) get only the origin |
| `Permissions-Policy` | camera, microphone, geolocation, payment, usb, interest-cohort, browsing-topics all `()` | a kids' game needs none of them |
| `Cross-Origin-Opener-Policy` | `same-origin` | isolates the browsing context |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | HTTPS only. No `preload`: `workers.dev` is Cloudflare's domain, and preload should be decided per custom domain |

### CSP

```
default-src 'self';
script-src 'self' 'unsafe-inline' https://static.cloudflareinsights.com;
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https://server.arcgisonline.com;
font-src 'self' data:; media-src 'self' data: blob:;
connect-src 'self' https://server.arcgisonline.com
            https://meridian-crash-report.knowledgetest.workers.dev
            https://cloudflareinsights.com;
worker-src 'self' blob:; child-src 'self' blob:; manifest-src 'self';
object-src 'none'; base-uri 'self'; form-action 'self';
frame-ancestors 'none'; upgrade-insecure-requests
```

- `'unsafe-inline'` scripts: TanStack Start's dehydration script is inline
  and changes on **every SSR response** (per-request router state and
  timestamps), so a build-time hash cannot match it on the worker. The
  Pages shell's crash watchdog and `?nosw=1` hatch are inline too. The fix
  is a per-request nonce on the worker, or hashes for the static shell
  (**P3 follow-up**).
- Analytics: Cloudflare Web Analytics only (`static.cloudflareinsights.com`
  script + `cloudflareinsights.com` beacon). Google and Clarity hosts are
  intentionally absent, and the test fails if one comes back.
- The contact form posts to `/api/contact` on the same `meridian` worker,
  so `'self'` already covers it and no extra host is needed. The GitHub
  Pages mirror posts cross-origin, which that handler's CORS allow-list
  governs, not this CSP: Pages serves no `_headers`.
- If `observabilityEndpoint` or `contactEndpoint` in `flags.json` ever
  points at a different host, add that host to `connect-src` in the same PR.
  For `observabilityEndpoint`, also add it to `OBSERVABILITY_INGEST_HOSTS`
  (review S3): the client refuses any ingest host not on that list.
- `frame-ancestors 'none'` also blocks embedding the *production* site in
  preview tools. Dev previews run on the Vite server and are unaffected.

## Caching

| Path | Cache-Control | Why |
| --- | --- | --- |
| `/assets/*` | `public, max-age=31536000, immutable` | content-hashed file names |
| `/assets/maplibre-gl-worker.mjs`, `/assets/maplibre-gl-shared.mjs`, `/assets/storyteller/storyteller-assets.json` | `! Cache-Control` (detach) **plus** `Cache-Control: public, max-age=0, must-revalidate` in the same block | fixed names with mutable content. The detach deletes the wildcard's `immutable` value, then the set stands alone as the path's only Cache-Control. Detach ALONE (PR #203) also deleted the platform default, so these files shipped with no Cache-Control at all — PR #212 fixed that by pairing the detach with the set |
| `/sw.js`, `/flags.json`, `/build-meta.json`, `/manifest.webmanifest` | `no-cache` | update detection and remote kill switches must see changes immediately |
| Rendered HTML on the Worker (`/`, `/privacy`, the 404 page, …) | `public, max-age=0, must-revalidate` | set by the request middleware (`HTML_CACHE_CONTROL` in `src/lib/security-headers.ts`) — the plain value with **no `s-maxage`**, owner-ruled 2026-10-22 (WI-18). `_headers` never reaches Worker-rendered pages, so this row — not the one below — is the live contract for rendered pages |
| `/`, `/index.html` (asset-served copies only) | `public, max-age=0, s-maxage=60, must-revalidate` | policy of record for an asset-served root (e.g. a static host serving the built document). The live site's pages are Worker-rendered and use the row above, so this rule never reaches them |

## Verify after deploy

```sh
curl -sI https://meridian.knowledgetest.workers.dev/ | grep -iE 'content-security|x-frame|strict-transport|permissions|cache-control'
curl -sI https://meridian.knowledgetest.workers.dev/assets/<any-hashed-file>.js | grep -iE 'cache-control|content-security|x-frame'
```

Check both paths: `/` (worker, from `src/start.ts`) and a hashed asset
(static, from `_headers`). If `/` is missing them after deploy, the deployed
worker is not running this repo's TanStack Start server entry. If an asset
is missing them, the build output is not being served as static assets.
